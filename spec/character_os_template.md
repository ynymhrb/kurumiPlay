# Character OS 输出模板

每个角色每个训练轮次应产出以下文件集（对照 `characters/<角色名>/V<版本号>/`，见 `eval_protocol.md` 第0节的轮次目录约定）：

```
characters/<角色>/
├── source/                 原文，各轮次共用
└── V<版本号>/
    ├── CEU/                 CEU 全集（按卷/cluster拆分）
    ├── ROUND_STATUS.md      查询"当前轮次做了哪些事"的唯一入口
    ├── value_hierarchy.md   价值排序
    ├── mental_models.md     Mental Models
    ├── decision_rules.md    Decision Heuristics
    ├── relationship_rules.md 关系/权力规则
    ├── expression_dna.md    语言习惯、口癖、修辞特征（用于 SFT 语言风格）
    ├── contradictions.md    模型无法解释的行为记录
    └── fidelity_test.md     用后续卷/盲测数据验证的记录
```

## value_hierarchy.md 结构

- 价值排序列表（从高到低），每条价值附上支撑它的 CEU 编号
- 排序应能解释：当两个价值冲突时，人物选哪个

## mental_models.md 结构

- 每个 Mental Model 一个小节：命名（如 MM1 至尊中心主义）+ 定义 + 支撑 CEU + 常见误读修正（如"爱导致失控"应修正为"爱成为战略行动驱动力"）
- **候选模型转正的三重验证标准**（采纳自外部参考`nuwa-skill`框架，原为真人思想者设计，调整为小说人物版）：
  1. **跨场景复现**：至少2个独立场景（不同cluster/不同卷）支持同一个模型，1个场景只能算"候选"，不能转正
  2. **有生成力**：能用这个模型推断人物在**新场景**下的选择方向，不是只能事后解释已有的CEU
  3. **有排他性**：这个模型体现的是这个角色的独特逻辑，不是"随便一个类似身份的角色都会这样想"的泛泛而谈
  - 只过1重验证 → 降级记为"候选"（如当前MM5/MM7），不写入正式结论性表述
  - 0重验证 → 不纳入mental_models.md，可能只是记入CEU的`underlying_belief`字段，不单独立模型
- 每个MM在文件里应标注当前满足几重验证（如"MM3：3/3，已转正"、"MM5：1/3，候选"），方便一眼看出哪些结论是稳的、哪些还在观察

## decision_rules.md 结构

- 编号列表的行为启发式（如"先确认至尊意志，再行动"），每条可标注适用场景和例外

## expression_dna.md 结构

详细方法论见 `expression_dna_protocol.md`（独立文件，因为这套量化方法本身有版本迭代）。这里只列产出应包含的最低要求：
- 语料池规模及来源（多少条台词、来自哪些CEU）
- 按场合拆分的句式指纹对比（不能只给一套不分场合的笼统印象）
- 候选口癖/句式，明确标注满足几次独立出现（<3次是候选，不是结论）
- 明确的"待补充"清单，不要用空泛描述掩盖"这块还没数据"的事实

## contradictions.md 结构

- 每条矛盾必须分类：**时间性矛盾**（观点/行为随时间演化）/ **领域性矛盾**（不同场合不同规则，非bug是深度来源）/ **本质性张力**（价值观内在冲突，本身有意义，不需要调和）
- **禁止的处理方式**：选一边忽略另一边、编一个调和的解释、假装矛盾不存在——领域性矛盾和本质性张力往往是模型里最有信息量的部分

## fidelity_test.md 结构

- 冻结当前模型版本号
- 用新卷逐个 CEU 验证：预测是否正确
- 记录预测失败的 CEU、失败原因、触发的模型修正（并同步写入 `logs/revision_log.md`）
- **失败时修改模型，不修改答案**

## 信息不足时的处理（适用于以上所有文件）

| 情况 | 处理 |
|---|---|
| 某个维度证据很少 | 标注"信息不足，此维度为初步观察"，不要用少量样本冒充结论 |
| 只有间接/概括性描述，无法确认细节 | 标注"仅有概括性描述，细节未展开"，不要脑补 |
| 证据相互矛盾且无法判断谁对 | 并列呈现，不要强行选一个 |
| 原文对某方面刻意不展开（如open_question类） | 如实记录"原文未透露"，不用小说后续剧情的先验记忆去填补 |

## 轮次冻结前的自检清单

冻结一个轮次（打round tag）之前，过一遍：

- [ ] 每个转正的Mental Model都有至少2个独立场景支撑？候选模型有没有被误当结论使用？
- [ ] Mental Model数量是否在合理区间（太少说明太浅，太多说明没有真正提炼、只是罗列）？
- [ ] expression_dna.md 是否仍是空的占位，还是有真实语料支撑的分析？
- [ ] contradictions.md 里的矛盾有没有被"选一边忽略另一边"式地悄悄处理掉？
- [ ] 是否所有 `schema_gap` 信号都在 `logs/schema_gaps.md` 里有复核记录，没有被无声丢弃？
- [ ] `logs/revision_log.md` 的记录是否都精确到具体子项，而不是"某文件改了"？
